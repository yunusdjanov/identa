# Medical Upload Security Design

## Goal

Harden patient media upload so uploaded medical images are not visible until they pass server-side validation, malware scanning, image sanitization, plan limits, and authorization checks.

## Scope

This design covers patient photos, treatment images, and odontogram entry images. It keeps the current Laravel API shape and existing frontend flows, but changes backend visibility semantics: newly uploaded media can be pending while queue processing finishes.

## Architecture

Uploads enter private quarantine storage first. A media processing job scans the quarantined object through an antivirus scanner interface, decodes and re-encodes the image, enforces stored-size limits, writes the approved object to a safe UUID path, and marks the media approved. Download endpoints only serve approved media after the existing owner, role, and permission checks pass.

The scanner is swappable. Production uses a private ClamAV daemon through `ANTIVIRUS_DRIVER=clamav`; tests and local development may bind a fake scanner. Scanner failures fail closed.

## Data Model

Patient photo metadata gains scan fields directly on `patients`. Treatment and odontogram images gain equivalent scan fields on their existing media tables.

Statuses:

- `pending`: uploaded to quarantine, not visible.
- `approved`: scanned and sanitized, visible.
- `rejected`: infected, invalid, oversized after sanitization, or scanner failure.

## Security Rules

- Original uploads are never served.
- Stored filenames are generated by the server.
- Final extension is selected from detected/sanitized MIME, not the user filename.
- Download requires approved status, tenant ownership, route permission, and authenticated user.
- Direct upload completion creates pending media only; visibility waits for processing.

## Testing Strategy

Feature tests cover approved-only downloads, rejected scanner results, and owner authorization staying intact. Unit tests cover scanner binding and image sanitizer fail-closed behavior.
